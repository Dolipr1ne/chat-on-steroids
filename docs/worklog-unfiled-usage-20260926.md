# Unfiled destinations and evidence-based Usage

## Root failures

An unfiled desktop chat can have the correct null project binding and still write into
an unrelated project. The command and direct patch handlers previously used the first
approved root when no caller workspace existed, unless a swarm was running. Permission
to access a directory is not a choice to use it as the task's destination. The global
New Chat action already clears project selection; changing session metadata would fix
the wrong owner and risk moving existing history.

Usage separately substituted GPT-5.6 High for activity without recorded model evidence.
The presentation grouped that guessed name with the Sol family and the cost calculator
applied its rate. An `(assumed)` suffix did not make those per-model totals truthful.
Worker usage is also included in the same overview and can legitimately name a model
that the user never selected for the parent conversation.

## Changes

An omitted command workdir or relative direct patch now requires the caller's own
project or learned workspace. No workspace produces `WORKSPACE_REQUIRED` before the
command or patch runs, independently of swarm activity. Explicit approved paths and
working directories remain supported; explicit project ownership, caller isolation,
permissions, traversal checks and terminal custody remain unchanged. Shell-intercepted
patches keep the explicitly selected command workdir.

Opening instructions identify unfiled chats and do not inject an unrelated project's
AGENTS.md. A new file request without an explicit local destination prefers a downloadable
chat file when the host supports it, otherwise asks where to save it. Existing task
paths and explicitly delegated worker destinations remain usable. This is not a new
OS sandbox: explicit authorized paths remain available, commands retain their documented
OS-account reach, and no new folder approval is granted.

Derived Usage cache version 10 replaces missing model evidence with an unknown model,
unknown effort and unpriced token subtotal. It rebuilds the previous cache from existing
recordings without editing messages, calls or historical model evidence. The compatibility
`assumed` field means missing model evidence, not a named-model guess. Legacy assumed
rows cannot be priced even when a matching rate remains in display preferences.

The model table lists observed models before the **Unknown model · not recorded** subtotal,
shows **Not estimated** instead of a model-specific price for that subtotal, and omits
its rate editor. A short explanation names both chat and worker activity. Total estimated
tokens, verified model usage, the comparison formula and saved rates remain intact.
Four new UI strings are translated through the existing six locale catalogues.

## Regression and integration evidence

Eight new tests failed before the repair: unfiled command destinations, cross-chat
workspace separation, opening scope, unknown attribution, matching-version cache
migration, stale assumed-row cost and renderer presentation. Additional real local MCP
tests prove that a missing destination creates no file, while an explicit approved
destination and a subsequently established relative base still work. The global New
Chat regression retains separate project/unfiled drafts through a history refresh.
A ninth regression found an adjacent path: a rejected absolute patch taught its
internal verifier root as the chat workspace. Verifier-base validation no longer
teaches a task destination; only actual approved hunk paths can establish one.

The nearest nine suites passed 334 tests with six platform/optional skips. The six
selected project/New Chat renderer cases and TypeScript passed. Real isolated Electron
exercised the production Usage renderer with unknown and recorded models, rate-editor
selection, native keyboard activation, exact message counts, persistence and wide/narrow
layouts. Its native-input assertion now waits for the actual renderer update instead
of treating dispatch as synchronous completion; it still sends real input events.

Final verification passed 6,167 tests with 46 skips in the general software run, plus
38 passed and one skipped in the unchanged native-exec suite run separately: **6,205
software tests passed, 47 skipped** in total. The separate shutdown suite passed all
six tests. TypeScript, production build, privacy and licence checks passed, and the
609 source/test/build inputs matched their frozen hashes afterward. The separate
foreground computer suite was not rerun for this update.

The exact local installer passed an isolated temporary-installation test: running-app
refusal, complete extra-file backups, archive replacement, idempotent repetition and
an unchanged companion directory remaining untouched. The staged payload verified
170 native files, 132 compiled files and 3,212 dependency files. Read-only preflight
against the existing installation passed; it did not install or restart the app.

## Delivery limits

This is a desktop-only repair; companion source and protocol are unchanged. A fresh
unfiled opening receives the revised setup instructions. Already frozen messages and
existing files are not rewritten or moved. Tests use isolated directories, endpoints,
settings and synthetic UI data. They do not prove a particular provider response will
obey the instructions or supply a downloadable artifact. No active user job was stopped,
no real project was reassigned, and no signed-in account conversation was changed for
validation. Existing API comparison rates were not changed or reverified here.
